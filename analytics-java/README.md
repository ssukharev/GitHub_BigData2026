# analytics-java

Анализ задач 1 и 3 на Java (JDBC + [Tablesaw](https://github.com/jtablesaw/tablesaw), регрессии — Apache Commons Math).

## Запуск

```
docker compose up -d                                      # из корня: PostgreSQL + миграции
cd collector/worldbank && mvn -q compile exec:java        # страны и население
cd ../innovation-graph && mvn -q compile exec:java        # разработчики, пуши, топики по странам
cd ../../analytics-java
mvn -q compile exec:java                                  # обе задачи: results/task1/ и results/task3/
mvn -q compile exec:java -Dexec.args=task1                # только задача 1 (или task3)
```

Подключение к БД — из `.env` в корне репозитория, как у сборщиков. SQL-запросы лежат в [`src/main/resources/sql`](src/main/resources/sql).

## Задача 1: влияние ИИ на работу на GitHub

Первый шаг — на данных Innovation Graph (2020Q1–2026Q2, все страны без агрегата EU). Данные GH Archive по событиям добавятся, когда появится их сборщик.

### Метод

- **Активность** ([`activity_by_quarter.sql`](src/main/resources/sql/task1/activity_by_quarter.sql)): разработчики и репозитории на конец квартала, пуши за квартал. Из них: прирост числа разработчиков за квартал, пушей на разработчика (только страны, где GitHub публикует пуши), репозиториев на разработчика. Innovation Graph публикует число аккаунтов на конец квартала, поэтому прирост — чистый: новые аккаунты минус удалённые, помеченные как спам или «переехавшие». Это не число регистраций.
- **ИИ-топики** ([`topics_by_quarter.sql`](src/main/resources/sql/task1/topics_by_quarter.sql)): Innovation Graph считает разработчиков, которые пушили в репозитории с данным топиком. Показатель — доля ИИ-топиков среди всех топиков, в процентах. Топики разбиты на четыре группы ([`AiTopics`](src/main/java/ru/spbstu/ghanalytics/analytics/task1/AiTopics.java), полный список — `ai_topic_groups.csv`):
  - **classic_ml** — машинное обучение до LLM (`machine-learning`, `deep-learning`, `pytorch`, …);
  - **general_ai** — `ai`, `artificial-intelligence`;
  - **llm** — LLM и их API (`llm`, `openai`, `chatgpt`, `langchain`, `rag`, `claude`, `gemini`, `ollama`, …);
  - **agents** — ИИ-агенты и ИИ-инструменты для кода (`ai-agents`, `mcp`, `claude-code`, `cursor`, `copilot`, `vibe-coding`, …).
- **По странам** ([`topics_by_country.sql`](src/main/resources/sql/task1/topics_by_country.sql)): та же доля за последний квартал, только страны, где всего не меньше 10 000 упоминаний топиков.
- **Сегментная регрессия** ([`SegmentedRegression`](src/main/java/ru/spbstu/ghanalytics/analytics/task1/SegmentedRegression.java), interrupted time series): `y = b0 + b1·t + b2·D + b3·(t − k)·D`. Проверяем, меняются ли уровень (`b2`) и наклон (`b3`) ряда после двух событий:
  - **ChatGPT** — первый полный квартал после выхода 2023Q1, окно 2020Q1–2024Q4;
  - **ИИ-агенты для кода** (Copilot agent mode, Claude Code, Codex — февраль–май 2025) — 2025Q2, окно 2023Q1–2026Q2.

  Соседние кварталы зависят друг от друга (автокорреляция), и обычные ошибки МНК от этого занижены. Поэтому p-значения считаются по устойчивым ошибкам Ньюи–Уэста (2 лага), а рядом выводится статистика Дарбина–Уотсона (около 2 — автокорреляции нет, заметно меньше 2 — положительная автокорреляция).

**ИИ-топики.** Доля ИИ среди всех топиков: 2,2% в 2022Q4 → 3,2% в 2023Q1 → 4,0% в 2024Q4 → 8,3% в 2025Q4 → **15,1% в 2026Q2**. Две волны видны по группам: LLM-топики появляются после ChatGPT (0,02% → 4,9%), топики агентов — в 2025 году (0,07% в 2024Q4 → 5,3% в 2026Q2). Классическое ML держится около 2–3%.

**Активность.** Разработчиков стало в 4,6 раза больше: 45,5 млн (2020Q1) → 209,1 млн (2026Q2). Прирост за квартал был около 4 млн в 2020–2021 годах, 5–7 млн в 2023–2024 годах и **16,8 млн в 2026Q2**. Пушей на разработчика с 2020 года становилось меньше (1,78 → 1,15 в 2024Q3), а с 2025 года их число растёт до **1,95** в 2026Q2. Всего пушей за пять кварталов стало в 2,3 раза больше (177,7 млн в 2025Q1 → 407,6 млн в 2026Q2).

Репозиториев на разработчика становится меньше: новые аккаунты пока заводят мало репозиториев.

**По странам, 2026Q2** (доля ИИ-топиков, 26 стран): Тайвань 35,6%, Сингапур 33,2%, Гонконг 29,9%, Южная Корея 28,3%, Китай 27,4%, … Великобритания 15,6%, США 14,8%, Индия 12,7%, Германия 11,7%, Бразилия 8,6%, Россия 7,4% (последнее место среди 26).

### Ограничения

- **Топики есть не у всех репозиториев**, и Innovation Graph публикует топик в стране, только если в него пушили не меньше 100 разработчиков. Доля ИИ-топиков — это доля среди помеченных репозиториев, а не всех.
- **Один разработчик считается в каждом своём топике**, поэтому сумма по топикам — это упоминания, а не люди. Доли от этого не зависят, абсолютные суммы — зависят.
- **В 2026 году GitHub стал публиковать больше топиков** (1145 в 2025Q4 → 2072 в 2026Q2). Проверка: если считать только топики, которые были уже в 2025Q4, доля ИИ в 2026Q2 даже выше — 16,0% вместо 15,1%. Среди новых топиков ИИ лишь 4,7%, так что расширение данных рост доли ИИ не создаёт, а немного занижает.
- **Пуши агентов.** ИИ-агенты пушат от имени пользователя, а GitHub исключает только аккаунты-боты. Значит, рост пушей на разработчика — это отчасти работа агентов, а не людей. Для статьи это скорее аргумент «ИИ меняет активность», но формулировать нужно аккуратно.
- **Регрессии простые**: без учёта сезонности (летом активность ниже). Автокорреляцию учитывают ошибки Ньюи–Уэста, но на 14–20 кварталах это приближение: p-значения — ориентир, а не строгий тест. Сильнее всего автокорреляция в доле ИИ-топиков вокруг ChatGPT (DW 0,84) и в репозиториях на разработчика (0,69), для них выводы стоит формулировать осторожнее. События выбраны заранее и обоснованы датами выхода продуктов.
- **Страна определяется по IP** (VPN, офисы в Сингапуре и Гонконге), как и в задаче 3.

## Задача 3: разработчики GitHub на душу населения

### Метод

- **Разработчики** — аккаунты GitHub, которые Innovation Graph относит к стране на конец IV квартала (боты исключены самим GitHub).
- **Население** — World Bank, `SP.POP.TOTL`, того же года. Поэтому годы 2020–2025: населения за 2026 ещё нет.
- **Показатель** — разработчиков на 1000 жителей ([`per_capita.sql`](src/main/resources/sql/task3/per_capita.sql)).
- Агрегаты World Bank (World, EU, группы стран) не участвуют. Экономики без населения в World Bank вынесены в отдельный список ([`no_population.sql`](src/main/resources/sql/task3/no_population.sql)).
- Рейтинг и рост считаются только по странам с населением от 1 млн: в микрогосударствах несколько тысяч аккаунтов дают значения, которые ничего не говорят о стране (например, Сейшелы — 173 на 1000).
- Регионы World Bank: сумма разработчиков, делённая на сумму населения, а не среднее по странам, — крупные страны весят больше. Гонконг и Сингапур в регионы не входят (см. оговорки), иначе они завышают Восточную Азию: 17,1 вместо 15,0 на 1000.

Расчёты — [`PerCapita`](src/main/java/ru/spbstu/ghanalytics/analytics/task3/PerCapita.java), тесты — `PerCapitaTest`.

### Оговорки для статьи

- **Гонконг и Сингапур.** 435 и 318 аккаунтов на 1000 жителей — это не «каждый третий житель — разработчик». GitHub определяет страну по IP-адресу, а через эти города идёт много VPN, прокси и офисов международных компаний. В рейтинге они остаются с пометкой, а в регионы не входят.
- **Рост.** Считаются все аккаунты в стране, а не активные разработчики, поэтому рост в 2–4 раза за пять лет — это и новые программисты, и накопление аккаунтов (у одного человека может быть несколько).
- **Тайвань** (1,74 млн аккаунтов в 2025 году) не попадает в расчёт: World Bank не публикует его население.
- Страны, где за квартал меньше 100 разработчиков, GitHub не публикует. Китай, вероятно, недооценён: часть разработчиков работает на Gitee.
