# analytics-java

Анализ задач 1 и 3 на Java (JDBC + [Tablesaw](https://github.com/jtablesaw/tablesaw), регрессии — Apache Commons Math).

## Запуск

```
docker compose up -d                                      # из корня: PostgreSQL + миграции
cd collector/worldbank && mvn -q compile exec:java        # страны и население
cd ../innovation-graph && mvn -q compile exec:java        # разработчики, пуши, топики по странам
cd ../../analytics-java
mvn -q compile exec:java                                  # обе задачи: results/task1/ и results/task3/
mvn -q compile exec:java -Dexec.args=task1                # только задача 1 (или task3)
mvn -q compile exec:java -Dexec.args=task1-gharchive      # независимый анализ снимка GH Archive
```

Подключение к БД — из `.env` в корне репозитория, как у сборщиков. SQL-запросы лежат в [`src/main/resources/sql`](src/main/resources/sql).

## Задача 1: влияние ИИ на работу на GitHub

Первый шаг — на данных Innovation Graph (2020Q1–2026Q2, все страны без агрегата EU). Второй, независимый шаг — на [опубликованном снимке GH Archive](https://github.com/ssukharev/GitHub_BigData2026/releases/tag/data-gharchive-2026-11-17) (2018–апрель 2025, см. ниже). Его отдельная команда не перезаписывает результаты Innovation Graph и задачи 3.

### Метод

- **Активность** ([`activity_by_quarter.sql`](src/main/resources/sql/task1/activity_by_quarter.sql)): разработчики и репозитории на конец квартала, пуши за квартал. Из них: прирост числа разработчиков за квартал, пушей на разработчика (только страны, где GitHub публикует пуши), репозиториев на разработчика. Innovation Graph публикует число аккаунтов на конец квартала, поэтому прирост — чистый: новые аккаунты минус удалённые, помеченные как спам или «переехавшие». Это не число регистраций.
- **ИИ-топики** ([`topics_by_quarter.sql`](src/main/resources/sql/task1/topics_by_quarter.sql)): Innovation Graph считает разработчиков, которые пушили в репозитории с данным топиком. Основной показатель — доля ИИ-топиков среди **тематических** топиков, в процентах.
  - **Служебные топики не учитываются** (`non_thematic_topics.csv`): `config`/`github-config` (репозитории настроек GitHub — от 0% упоминаний в 2020Q1 до 47% в 2021–2022, они создавали ложный «спад» доли ИИ и большую часть «скачка» после ChatGPT), Hacktoberfest и другие акции (пик каждый октябрь), учебные задания, портфолио, профили, шаблоны. Правила — [`AiTopics.NON_THEMATIC`](src/main/java/ru/spbstu/ghanalytics/analytics/task1/AiTopics.java).
  - **Как составлен список ИИ-топиков**: топик считается ИИ, если в его названии есть ИИ-слово (`ai`, `llm`, `gpt`, `agent`, `neural`, `ml`, `diffusion`, `copilot`, …), кроме вручную отклонённых неоднозначных (`virtual-machine`, `state-machine`, `lora` — радио LoRa, `causal-inference`, `apm-agent`, …). Группа — по словам названия: агенты и ИИ-инструменты для кода → LLM и генеративный ИИ → классическое ML → иначе общий ИИ. Несколько топиков без таких слов (`chatgpt`, `artificial-intelligence`, `natural-language-processing`) добавлены вручную. Все кандидаты из данных с решением по каждому — в `ai_topic_review.csv` (206 кандидатов: 192 ИИ и 14 отклонённых), итоговый список по группам — `ai_topic_groups.csv`:
    - **classic_ml** (31) — машинное обучение до LLM (`machine-learning`, `deep-learning`, `pytorch`, `computer-vision`, …);
    - **general_ai** (40) — общие ИИ-метки (`ai`, `artificial-intelligence`, `chatbot`, `ai-tools`, `ai-safety`, …);
    - **llm** (62) — LLM и генеративный ИИ (`llm`, `openai`, `chatgpt`, `rag`, `claude`, `gemini`, `deepseek`, `qwen`, `embeddings`, `stable-diffusion`, …);
    - **agents** (59) — ИИ-агенты и ИИ-инструменты для кода (`ai-agents`, `mcp`, `claude-code`, `codex`, `cursor`, `copilot`, `langgraph`, `vibe-coding`, …).
  - **Проверочный показатель** — ИИ-упоминаний на 1000 разработчиков (`ai_per_1000_developers`): он вообще не зависит от остальных топиков, то есть не может быть артефактом знаменателя. Зато он чувствителен к тому, сколько топиков GitHub публикует (в 2026 году их стало почти вдвое больше).
- **По странам** ([`topics_by_country.sql`](src/main/resources/sql/task1/topics_by_country.sql)): GitHub публикует топик в стране, только если в нём не меньше 100 разработчиков, поэтому списки топиков у стран очень разные (1683 у США, 85 у России в 2026Q2) и доли «по своим топикам» несравнимы. Доля считается **на общем наборе топиков**, опубликованных для всех сравниваемых стран (25 стран, где не меньше 10 000 тематических упоминаний): это 22 топика, из них ИИ — `ai`, `ai-agents`, `claude-code`, `llm`, `rag` (`ai_topics_by_country_common_topics.csv`). Доля по собственным топикам страны оставлена для сравнения (`ai_share_own_topics_pct`).
- **Сегментная регрессия** ([`SegmentedRegression`](src/main/java/ru/spbstu/ghanalytics/analytics/task1/SegmentedRegression.java), interrupted time series): `y = b0 + b1·t + b2·D + b3·(t − k)·D`. Проверяем, меняются ли уровень (`b2`) и наклон (`b3`) ряда после трёх событий (первый полный квартал после события):
  - **превью GitHub Copilot** (29.06.2021) — 2021Q3, окно 2020Q1–2022Q4. Общий доступ к Copilot (21.06.2022, 2022Q3) всего за два квартала до ChatGPT, по квартальным данным их не разделить: он отмечен на графиках, но отдельно не проверяется;
  - **ChatGPT** (30.11.2022) — 2023Q1, окно 2020Q1–2024Q4;
  - **ИИ-агенты для кода** (агентный режим Copilot, Claude Code, Codex — февраль–май 2025) — 2025Q2, окно 2023Q1–2026Q2.

  p-значения — по устойчивым к автокорреляции ошибкам Ньюи–Уэста (2 лага), рядом статистика Дарбина–Уотсона (около 2 — автокорреляции нет).
- **Проверка на ложных датах (placebo)**: та же модель с разломом в каждом другом квартале окна (не ближе 3 кварталов к краям). В таблице — доля таких подставных дат, у которых p-значение не больше, чем у настоящего события. Если доля маленькая (до ~0,1), настоящее событие выделяется; если большая — похожий «разлом» находится почти везде, то есть ряд просто плавно изгибается и дату перелома по данным определить нельзя. Все подставные регрессии — `placebo_breaks.csv`.

### Ограничения

- **Топики есть не у всех репозиториев**, и Innovation Graph публикует топик в стране, только если в него пушили не меньше 100 разработчиков. Доля ИИ — доля упоминаний «разработчик × топик» среди опубликованных тематических упоминаний. Это не доля репозиториев и не доля уникальных людей.
- **Один разработчик считается в каждом своём топике**, поэтому сумма по топикам — это упоминания, а не люди.
- **Служебные топики** определены правилами по названию; полный список исключённого — `non_thematic_topics.csv`. Без исключения `config`/`github-config` выводы о 2020–2023 годах были бы ошибочными.
- **Список ИИ-топиков** зависит от правил и ручных решений; все спорные случаи видны в `ai_topic_review.csv`.
- **В 2026 году GitHub стал публиковать больше топиков** (1117 тематических в 2025Q4 → 2045 в 2026Q2). На фиксированном наборе топиков 2025Q4 доля ИИ в 2026Q2 — 20,0% вместо 19,8%; на фиксированных парах «страна × топик» — 17,4%. Значит, расширение списка топиков само по себе не объясняет рост, но часть роста связана с преодолением порога публикации в новых странах. Эти дополнительные проверки воспроизведены на [ревью 17 ноября](https://github.com/ssukharev/GitHub_BigData2026/pull/23#pullrequestreview-5937892076); основной CSV не содержит их отдельных результатов. Показатель на 1000 разработчиков тоже чувствителен к расширению публикации.
- **Короткая база до событий.** Innovation Graph начинается с 2020Q1: до превью Copilot всего 6 кварталов, до ChatGPT — 12. Более ранний тренд по этим данным не проверить.
- **Сравнение стран** опирается на 22 общих топика, из них 5 ИИ; оно отражает популярные ИИ-темы, а не все.
- **Пуши агентов.** ИИ-агенты могут пушить от имени пользователя; доля таких действий неизвестна. Рост пушей на разработчика сам по себе не доказывает рост ручной работы или производительности.
- **Регрессии простые**: без учёта сезонности; на 12–20 кварталах ошибки Ньюи–Уэста — приближение, p-значения — ориентир. Поэтому важнее результат placebo, чем само p.
- **Совпадение во времени — не причина.** События выбраны заранее по датам выхода продуктов, но в те же периоды могли действовать и другие факторы.

### GH Archive: месячная динамика и сравнения

Для запуска `task1-gharchive` в мигрированной базе должны быть восстановлены обе таблицы GH Archive из релиза `data-gharchive-2026-11-17` (файл `gharchive-2026-11-17.dump`, SHA-256 `58c9b12434b019f3be7452f55326675c887066638b6b033f0c83b41e56157fdf`). Повторная выгрузка из ClickHouse не требуется. Команда использует только чтение из `marts.gh_activity_monthly_valid` ([SQL](src/main/resources/sql/task1/gharchive_monthly.sql)).

- Сопоставимый период — январь 2018 — апрель 2025, до разрыва охвата источника 23 мая 2025. Месяцы с покрытием часов менее 97% или аномально низкой суточной активностью помечаются `known_gap` согласно [матрице валидности](../docs/gharchive-limits.md). Значения сохраняются для аудита, но не участвуют в сравнениях. В снимке 88 месяцев, пять помечены (2019-09, 2020-08, 2021-08, 2021-10, 2022-03), целиком отсутствующих нет. Пропущенные метрики остаются пустыми (например, `new_repos_bot` за 2018-09), а не нулём.
- Показатели: число `PushEvent`, приближённое число уникальных логинов и имён репозиториев с пушами за месяц, прокси коммитов `sum(least(push_distinct_size, 100))` и число `CreateEvent:repository` (без повторного учёта родительского `CreateEvent`). Каждый показатель разделён по суффиксу `[bot]`. Отсутствие суффикса не доказывает, что пуш сделан человеком. Приближённые distinct-метрики не суммируются по месяцам или группам.
- Сравнения: 12 месяцев до и после первого полного месяца с превью Copilot (2021-07), GA Copilot (2022-07) и ChatGPT (2022-12); дополнительно январь–апрель каждого года с теми же месяцами предыдущего года, 2019–2025. Сравниваются только пары месяцев с разницей ровно в год; если один из них отмечен разрывом, отсутствует или метрика неизвестна, исключается пара целиком. В расчёте — средние по совпавшим календарным месяцам, относительное изменение средних; для средней месячной доли пушей `[bot]` — разность в процентных пунктах.

## Задача 3: разработчики GitHub на душу населения

### Метод

- **Разработчики** — аккаунты GitHub, которые Innovation Graph относит к стране на конец IV квартала (боты исключены самим GitHub).
- **Население** — World Bank, `SP.POP.TOTL`, того же года. Поэтому годы 2020–2025: населения за 2026 ещё нет.
- **Показатель** — разработчиков на 1000 жителей ([`per_capita.sql`](src/main/resources/sql/task3/per_capita.sql)).
- Агрегаты World Bank (World, EU, группы стран) не участвуют. Экономики без населения в World Bank вынесены в отдельный список ([`no_population.sql`](src/main/resources/sql/task3/no_population.sql)).
- Рейтинг и рост считаются только по странам с населением от 1 млн: в микрогосударствах несколько тысяч аккаунтов дают значения, которые ничего не говорят о стране (например, Сейшелы — 173 на 1000).
- Регионы World Bank: сумма разработчиков, делённая на сумму населения, а не среднее по странам, — крупные страны весят больше. Гонконг и Сингапур в регионы не входят (см. оговорки), иначе они завышают Восточную Азию: 17,1 вместо 15,0 на 1000.

Расчёты — [`PerCapita`](src/main/java/ru/spbstu/ghanalytics/analytics/task3/PerCapita.java), тесты — `PerCapitaTest`.

### Оговорки для статьи

- **Гонконг и Сингапур.** 435 и 318 аккаунтов на 1000 жителей — это не «каждый третий житель — разработчик». GitHub определяет страну по IP-адресу, а через эти города идёт много VPN, прокси и офисов международных компаний. В рейтинге они остаются с пометкой, а в регионы не входят.
- **Рост.** Считаются все аккаунты в стране, а не активные разработчики, поэтому рост в 2–4 раза за пять лет — это и новые программисты, и накопление аккаунтов (у одного человека может быть несколько).
- **Тайвань** (1,74 млн аккаунтов в 2025 году) не попадает в расчёт: World Bank не публикует его население.
- Страны, где за квартал меньше 100 разработчиков, GitHub не публикует. Китай, вероятно, недооценён: часть разработчиков работает на Gitee.
