# Качество данных полного сбора (ноябрь 2026)

Отчёт к issue #56. Проверки - `sql/quality/checks.sql`, запуск 23.11.2026 на локальной базе, из
которой собраны релизы `data-repos-2026-11-19`, `data-commits-2026-11-20` и
`data-gharchive-2026-11-17`. Блокирующая проверка (`[block]`) должна вернуть пустой результат или
каждая её строка объяснена ниже; информационная (`[info]`) даёт числа для раздела статьи "Данные".

```bash
set -a && . ./.env && set +a
PGPASSWORD="$POSTGRES_PASSWORD" psql -h localhost -p "${POSTGRES_PORT:-5432}" -U "$POSTGRES_USER" \
     -d "$POSTGRES_DB" -f sql/quality/checks.sql > quality.out
```

Запускать из корня репозитория: скрипт читает `docs/data/sample-windows.csv` и
`population-by-month.csv` через `\copy`, потому что таблиц выборки в базе пока нет (#58). Скрипт
только читает: всё, что он создаёт, - временные таблицы сеанса.

Для повторения на восстановленных релизах нужно явно передать
`-v commit_collection_week=2026-11-15` в команду `psql`: в дампах нет
`collection_runs` и `checkpoints`. Без этого параметра скрипт использует последний успешный
запуск `github-commits`, а при отсутствии и запуска, и параметра останавливается, чтобы проверка
будущих недель не выдавала ложный пустой результат. Значение должно быть воскресеньем UTC и
соответствовать снимку, не текущей дате. Распределение причин отсутствия статистики (Q10, Q10d)
и стоимость сборов (Q13b) в этом отчёте взяты из исходного журнала и чекпоинтов, а не
восстанавливаются из опубликованных дампов.

С 23.11.2026 публичный дамп репозиториев не содержит README (#55). Для повторения Q06–Q07
нужен полный снимок, переданный команде приватно. На публичном дампе Q06 покажет отсутствие
строк, а Q07 — отсутствие проверенных README и неопределённую долю отсутствующих среди
проверенных. Это не отсутствие README у самих репозиториев. Остальные данные снимков не менялись.

**Выборка** - репозитории, у которых `created_at` попадает в окно `sample-windows.csv`. В
`core.repos` 5492 строки: 5250 в выборке (ровно столько, сколько в CSV) и 242 строки января 2024 из
тестового набора `data-sample-2026-11-04`. Проверки выборки их не видят; проверки целостности
таблиц идут по всем строкам.

## Итог

Ошибок сборщиков не найдено. Из 14 блокирующих проверок пусты 10. Непустые четыре объясняются
свойствами источников, а не нашими данными: у одного репозитория GitHub сам противоречит себе в
числе релизов, у одного `contributors_total` на 2 меньше числа авторов в статистике, а в GH Archive
есть известные дыры (65 суток с неполной сеткой часов и 19 суток с провалом push).

  остановки по квоте даёт окнам разного размера разные шансы попасть в выборку, контрпример - в

- Кластеры: 1229 окон по 10 минут, в окне в среднем 4,3 репозитория (медиана 4, максимум 21), Q05g.

### Известные особенности данных

- **Накрутка звёзд** (Q05h): в выборке две группы пустых репозиториев одного окна с одинаковым числом
  звёзд, без описания и языка - 2024-05-19 10:40 UTC (8 репозиториев у 2 аккаунтов, по 21 звезде) и
  2025-02-25 14:30 UTC (16 репозиториев у 5 аккаунтов, по 17 звёзд). Всего 24 (0,46%). Оценка "около
  28" в `heuristics-notes.md` шире: она включала похожие репозитории вне этих двух групп. Для задач 1 и
  4 их стоит исключать фильтром, для задачи 5 это `unclear`.
- **Внешние ограничения источников** не повторяются здесь: обрезка списка авторов и история до
  `created_at` - в `commit-activity-notes.md`, матрица валидности GH Archive - в `gharchive-limits.md`,
  эвристики `has_*` - в `heuristics-notes.md` (их точность проверяется отдельно, #57).

Полную загрузку GH Archive остановили вручную в запуске 4 (12 минут, в журнале `failed`, счётчики не
сохранились), запуск 5 продолжил её с `--resume` (5 минут, 67 запросов ClickHouse, 92,2 млрд
прочитанных строк). Поэтому стоимость берём из замера по задачам в `gharchive-limits.md`, раздел
"Бюджет полной загрузки": 103,7 млрд прочитанных строк, 35% часовой квоты. Запуски 1 и 2 - пробные
(один день 2024-03-06), 3 и 7 - проверки отдельных месяцев.

## Что из этого следует для анализа

- Для долей по совокупности - веса, с оговоркой, что это приближение; без весов доли описывают выборку.
- Последнюю неделю `repo_commits_weekly` (2026-11-15) отбрасывать.
- Обрезанные `stats_truncated` и история до `created_at` - фильтр или явная оговорка в каждом
  выводе про объём коммитов.
- Две группы накрученных репозиториев - фильтр по Q05h.
- В рядах GH Archive пропущенный час - `NULL`, а не ноль; абсолютные значения сравнимы только в
  2018-01..2025-04.
