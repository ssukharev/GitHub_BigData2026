# analytics-py

`ghdata` выгружает таблицы PostgreSQL в pandas. Задача 5 сравнивает типы репозиториев
по проверенной разметке; сборщики звёзд и задачи 2/4 разрабатываются отдельно.

## Установка

Из корня репозитория:

```bash
python -m venv analytics-py/.venv
source analytics-py/.venv/bin/activate
pip install -e "analytics-py[dev]"
```

Подключение берётся из `DATABASE_URL` либо `POSTGRES_HOST`, `POSTGRES_PORT`,
`POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` в окружении/корневом `.env`.
Перед запуском примените миграции V1–V4 и восстановите опубликованные данные
[data-repos-2026-11-19](https://github.com/ssukharev/GitHub_BigData2026/releases/tag/data-repos-2026-11-19).
Дамп содержит 5 492 репозитория (5 250 основной выборки и 242 тестовых).

## Проверенная разметка

[Руководство](../docs/data/task5-labeling-guide.md) и
[CSV](../docs/data/task5-manual-labels.csv) содержат 150 репозиториев тестовой выборки
января 2024. **Метки предложены LLM и проверены Стасом**, а не независимо размечены
несколькими людьми. `source=manual` означает эту проверку; `labeled_by` сохраняет
`statf0rd:human-reviewed-llm`.

CSV идентифицирует репозиторий по `full_name`, не по `repo_id`. Импортёр понимает
UTF-8 BOM, сопоставляет имена без учёта регистра и до записи проверяет весь файл:
дубликаты, неизвестные имена, классы, уверенность и пояснения. Все изменения
выполняются одной транзакцией; повторный импорт обновляет те же строки и не трогает
метки других источников.

```bash
python -m ghdata.manual_labels docs/data/task5-manual-labels.csv
python analytics-py/notebooks/task5_classification.py
```

Либо импорт и оценка одной командой:

```bash
python analytics-py/notebooks/task5_classification.py --labels-csv docs/data/task5-manual-labels.csv
```

`--labels-csv ... --no-save` оценивает именно этот CSV, не записывая метки в БД.
Обычный запуск без CSV только читает уже импортированные метки. Пустая БД,
отсутствующая V4, ошибка запроса или отсутствие проверенных меток останавливают
запуск. Автоматической замены данных синтетикой нет; LLM-запросы при оценке не делаются.

## Протокол оценки

1. Используются только `manual`-метки. `heuristic`/непроверенные `llm` исключены.
   Проверяются уникальность `repo_id`, классы и происхождение меток.
2. Шесть `unclear` исключаются: остаются 144 репозитория семи классов.
3. После сортировки по ID фиксированный seed 42 делит данные стратифицированно:
   108 train и 36 test. Один ID не может попасть в обе части.
4. TF-IDF, кодирование категорий и масштабирование обучаются внутри sklearn Pipeline
   на соответствующем train-fold. По четырёхчастной CV на train выбирается модель
   с максимальным macro-F1; при равенстве — по имени модели. Test не участвует в выборе.
5. Только выбранная модель один раз оценивается на test. Рядом — majority baseline,
   обученный на train. Таблица сравнения моделей содержит CV-метрики, не тестовые оценки
   всех кандидатов.

Результаты в [`results/task5/`](results/task5/): `cv_metrics.csv`, `test_metrics.csv`,
`split.csv` с ID, метками, происхождением и test-предсказаниями, `class_counts.csv`,
`reviewed_labels.csv`, `classification_report.txt`, `manifest.json` с seed, версиями,
размерами частей и SHA-256 входных признаков/CSV; `environment.txt` фиксирует версии
окружения опубликованного эксперимента. Два реальных рисунка —
[`распределение`](../docs/figures/task5_class_distribution.png) и
[`матрица ошибок`](../docs/figures/task5_confusion_matrix.png).

## Реальный базовый эксперимент, 22.11.2026

Дамп `repos-2026-11-19.dump` (SHA-256
`6dbdcb2388f3284701dc50ed238213e7b5c9f74f25e0bca90686f5aec5e1bb29`)
восстановлен в отдельную PostgreSQL 16; импортированы все 150 проверенных меток.
Новые LLM-метки и синтетические строки не использовались.

| Модель | CV macro-F1 | CV std |
|---|---:|---:|
| RandomForest | 0,3862 | 0,0649 |
| LinearSVC | 0,3339 | 0,0466 |
| LogisticRegression | 0,3281 | 0,0691 |

| Модель на test (36 репозиториев) | Accuracy | Macro-F1 | Weighted-F1 |
|---|---:|---:|---:|
| Выбранная RandomForest | 0,5278 | 0,2860 | 0,4706 |
| Majority baseline | 0,5000 | 0,0952 | 0,3333 |

Это слабый базовый результат, а не готовый надёжный классификатор. Для `library`,
`framework` и `dataset` test F1 равен нулю; в test у этих классов только 4, 1 и 2 примера.
Разница accuracy с baseline — один правильный ответ. Нельзя делать вывод об уверенном
превосходстве по общей точности или обобщать результат на все GitHub-репозитории.

Ограничения: малая и несбалансированная выборка только января 2024, отбор исходного
тестового набора по звёздам, метки с участием LLM и одного проверяющего. Разделение
выполнено по репозиториям; один автор или похожие шаблоны могут встретиться в обеих
частях. Нужны дополнительная проверенная разметка редких классов и проверка на других
годах/авторах. Метаданные и README соответствуют снимку сбора, не состоянию при создании.
Опубликованный test нельзя далее использовать как validation для подбора признаков/параметров.

## Явное демо и проверки

```bash
python analytics-py/notebooks/task5_classification.py --demo
ruff check analytics-py
pytest analytics-py/tests
```

Демо никогда не читает/не пишет БД. Все его артефакты помечены «ДЕМО» и сохраняются
только в игнорируемый `analytics-py/results/demo/task5/`, отдельно от `docs/figures/`
и реальных результатов. Его качество не оценивает реальные проекты.

Три PostgreSQL-теста импортёра требуют явно заданный `TASK5_TEST_DATABASE_URL`,
указывающий **на отдельную тестовую БД** с миграциями. Без него эти три теста
пропускаются. Они создают и удаляют только свои искусственные репозитории; проверяют
повторный импорт, отсутствие частичной записи и откат при ошибке второй записи.
